Documentation

Everything needed to pull media out of 18 social platforms — as a library, as a CLI, or as a piece of something bigger.

Installation

Ember needs Python 3.9 or newer. The distribution is named ember-dl, the import name stays ember:

pip
pip install ember-dl

Latest development version straight from Git:

pip · git
pip install git+https://github.com/smeshidojoe/Ember.git

After installation both the Python API (import ember) and the ember command are available. The only required dependency is requests.

When you need ffmpeg

Most downloads work without it. Put ffmpeg on your PATH if you need:

  • muxing separate video + audio tracks (results with kind="merge");
  • audio-only extraction (audio_only=True / --audio-only);
  • writing metadata into the file (embed_metadata=True).

Direct mp4 and single-stream HLS assemble on their own. Check at runtime with ember.ffmpeg_available().

Quick start

Two steps: extract, then optionally download. extract() never fetches media bytes — it only resolves links and metadata.

quickstart.py
import ember

# 1) direct links and metadata
result = ember.extract("https://vimeo.com/76979871")
print(result.title, result.author, result.thumbnail)
for m in result.media:
    print(m.kind, m.quality, m.url)

# 2) download with Ember itself (no yt-dlp needed)
def on_progress(p: ember.DownloadProgress):
    if p.fraction is not None:
        print(f"{p.fraction*100:.0f}%")

paths = ember.download(
    result, "downloads/",
    max_height=720,          # cap quality
    concurrency=6,           # parallel HLS segments
    on_progress=on_progress,
    embed_metadata=True,     # title/author (ffmpeg)
)

Useful checks before committing to a download:

checks.py
ember.can_extract(url)                       # is the link supported
ember.available_qualities(result.media[0])   # [1080, 720, 480]
ember.probe_size(result.media[0])            # bytes, one HEAD-ish request
ember.ffmpeg_available()                    # is ffmpeg on PATH
ember.supported_services()                  # list of service names

Command line

Quote the URL. Flag order doesn't matter. Without -d nothing is downloaded — the command only prints links and metadata.

terminal
# show direct links and metadata
ember "https://x.com/user/status/123456789"

# same, as JSON
ember "https://www.tiktok.com/@user/video/7123456789" --json

# DOWNLOAD: -d enables it (name from the site, current folder)
ember -d "https://vimeo.com/76979871"

# custom file name (-o) and folder (-p)
ember -d -o myclip -p downloads "https://vimeo.com/76979871"

# cap quality, fetch HLS in 6 threads
ember -d -p downloads --max-height 720 --concurrency 6 "<url>"

# audio only + write metadata into the file (needs ffmpeg)
ember -d --audio-only --embed-metadata "<soundcloud url>"

# a whole playlist / set
ember -d --playlist "https://soundcloud.com/user/sets/name"

# links from a file, one per line (# = comment)
ember -d -a links.txt

List available qualities and exit without downloading: ember -F "<url>". Full help: ember --help.

Quality & formats

A Result holds one or more Media objects. Progressive media carry alternative heights in variants; HLS media resolve their ladder from the master manifest.

quality.py
heights = ember.available_qualities(result.media[0])   # [1080, 720, 480]

# cap the whole download
ember.download(result, "out/", max_height=720)

# or one media item, with your own filename
path = ember.download_media(result.media[0], "out/clip.mp4",
                            max_height=720, concurrency=6)
Building a UI? probe_size() returns the byte size using the same access profile as the real download, so a size shown in your quality selector is the size the user gets.

Cookies

Some content is only served to logged-in users: NSFW tweets, private and full-quality Instagram posts, closed VK groups, most Facebook video. Ember reads cookies straight from a browser.

cookies
# Python
result = ember.extract(url, cookies_from_browser="firefox")
result = ember.extract(url, cookies={"auth_token": "…", "ct0": "…"})

# CLI
ember --cookies-from-browser firefox "<url>"
ember --cookies "auth_token=…; ct0=…" "<url>"
ember --cookies-file cookies.txt "<url>"       # Netscape format

Which browser to use

  • Firefox — recommended, reads out of the box on any OS.
  • Vivaldi, Opera and other non-Chrome Chromium browsers on Windows also work.
  • Recent Chrome, Edge, Brave encrypt their cookie store (App-Bound Encryption) and usually cannot be read.
Tip — keep a dedicated cookies browser. Install a browser you don't otherwise use, sign in to the services you plan to pull from, then leave it closed. The sessions stay valid, and your main browser is never touched.

Pick a profile with browser_profile= / --browser-profile. The reader is native (no extra packages) with yt-dlp and browser_cookie3 as optional fallbacks.

Playlists & timelines

A playlist is a set (currently SoundCloud sets). A timeline is an author's latest posts, resolved from a profile or channel URL.

bulk.py
if ember.supports_playlist(url):
    for entry in ember.extract_playlist(url).entries:
        ember.download(entry, "downloads/")

# latest posts by profile URL, e.g. "https://x.com/nasa"
if ember.supports_timeline(url):
    for entry in ember.extract_timeline(url, limit=30).entries:
        ember.download(entry, "downloads/")

Timelines are supported for SoundCloud, VK, Twitch, Tumblr, Rutube, Vimeo, Pinterest, Twitter/X and Instagram. The last two may need cookies or a non-blocked IP.

Embedding Ember

The intended pattern: try Ember, fall back to yt-dlp for anything outside its scope.

embed.py
import ember

def fetch(url: str, out_dir: str):
    if not ember.can_extract(url):
        return run_ytdlp(url)              # your fallback
    try:
        result = ember.extract(url)
    except ember.EmberError:
        return run_ytdlp(url)
    return ember.download(result, out_dir, concurrency=6)
Media objects carry http_headers. If you hand URLs to your own downloader instead of using download(), pass those headers along — TikTok answers 403 without them.

API — extraction

extract(url, *, timeout=15.0, proxies=None, cookies=None, cookies_from_browser=None, browser_profile=None, session=None) → Result

Extract direct media links and metadata from a post URL.

  • url — post / track / video link.
  • timeout — per-request timeout in seconds.
  • proxies — requests-style dict, e.g. {"https": "http://host:port"}.
  • cookies — {name: value} for private or NSFW content.
  • cookies_from_browser — "firefox", "vivaldi", "chrome", …
  • session — bring your own requests.Session.
  • raises UnsupportedUrlError, NetworkError, ExtractionError.

extract_playlist(url, **kwargs) → Playlist

Extract a set or playlist. A single link yields a Playlist with one entry.

extract_timeline(url, *, limit=30, **kwargs) → Playlist

List an author's latest posts by profile or channel URL, up to limit.

can_extract(url) → bool

True when the URL matches a supported service.

supports_playlist(url) → bool · supports_timeline(url) → bool

Whether playlist or timeline extraction is available for that URL.

supported_services() → list[str]

Names of all available services.

API — download

download(result, out_dir=".", *, filename=None, max_height=None, concurrency=1, on_progress=None, audio_only=False, embed_metadata=False, subtitles=False, thumbnail=False, write_info=False) → list[str]

Download an entire Result. Returns the paths written.

  • filename — base name without extension (default: from metadata).
  • max_height — cap quality by height, e.g. 720.
  • concurrency — parallel HLS segments.
  • on_progress — callback receiving DownloadProgress.
  • audio_only, embed_metadata — need ffmpeg.
  • subtitles, thumbnail, write_info — extra sidecar files.

download_media(media, out_path, *, max_height=None, concurrency=1, on_progress=None, resume=True, audio_only=False, meta=None) → str

Download a single Media. Returns the actual path — the extension may become .ts when ffmpeg is missing.

available_qualities(media) → list[int] · probe_size(media) → int | None · ffmpeg_available() → bool

Quality ladder, byte size before downloading, and ffmpeg presence.

cookies_from_browser(browser, service=None, profile=None) → dict

Read cookies from a browser, optionally limited to one service's domains.

API — data models

Result

  • service: str, source_url: str.
  • kind: str — "single", "merge" (separate video+audio, needs ffmpeg) or "gallery".
  • media: list[Media], subtitles: list[Subtitle].
  • title, author, thumbnail, filename_hint — all optional.
  • duration, timestamp, view_count, like_count — when the service reports them.
  • requires_merge: bool (property), to_dict().

Media

  • kind — "video", "audio", "photo" or "gif".
  • url, ext, quality.
  • http_headers: dict — pass these to your own downloader.
  • variants: list[MediaVariant] — other progressive qualities.

Playlist · Subtitle · MediaVariant

Playlist holds entries: list[Result] plus service and title. Subtitle has lang, url, ext. MediaVariant has url, height, quality, ext.

DownloadProgress

Passed to on_progress: downloaded, total, segments_done, segments_total, stage ("download" / "mux" / "metadata") and the fraction property. Speed and ETA are not fields — time them yourself:

speed.py
import time
start = time.time()

def on_progress(p: ember.DownloadProgress):
    if not p.total:                  # HLS / unknown size
        return
    speed = p.downloaded / (time.time() - start)
    eta = (p.total - p.downloaded) / speed if speed else 0
    print(f"{p.fraction*100:5.1f}%  {speed/1048576:.2f} MiB/s  ETA {int(eta)}s")

API — errors

Everything inherits from EmberError, so one except covers the library:

  • UnsupportedUrlError — hand the link to yt-dlp instead.
  • NetworkError — transport failure, timeout, blocked IP.
  • ExtractionError — the page loaded but no media could be resolved.

API — logging

Ember logs to the ember logger (children: ember.router, ember.http, ember.cookies, ember.download) and is silent by default via NullHandler.

logging.py
import logging
logging.basicConfig()
logging.getLogger("ember").setLevel(logging.INFO)   # or DEBUG

On the CLI use -v for stderr logs and -vv for debug.

Limitations

  • Instagram — anonymously often preview-only; cookies give full quality.
  • Reddit, Newgrounds, OK.ru — block anonymous requests from datacenter and VPN addresses; they work from a home IP or through proxies= / --proxy.
  • Facebook — public video usually still requires cookies.
  • Twitter / X — NSFW tweets require account cookies (auth_token and ct0).
  • Twitch — clips only, not VODs or live streams.
  • YouTube — out of scope by design; use yt-dlp.
